# **GitLab CI/CD pipeline run automatically on every code push** (no manual trigger needed).

Here’s a **step-by-step guide** with explanation and example 👇

---

## 🚀 Goal

Automatically trigger a GitLab CI/CD pipeline whenever a commit is **pushed** to your repository (any branch or specific ones).

---

## 🧩 Step 1: Ensure GitLab Runner is Configured

Before the pipeline can run:

1. Go to **GitLab → Settings → CI/CD → Runners**.
2. Ensure there’s either:

   * A **Shared Runner** (provided by GitLab), OR
   * A **Specific Runner** (you installed manually on your VM or server).
3. The runner should be **“active”** and **“online”**.

✅ Tip: For small personal projects, using GitLab’s shared runners is easiest.

---

## 🧾 Step 2: Create the `.gitlab-ci.yml` File

This is the CI/CD pipeline definition file.

At the **root of your repo**, create a file named:

```
.gitlab-ci.yml
```

Here’s a simple example that runs automatically on **every push**:

```yaml
stages:
  - build
  - test
  - deploy

# Build stage
build_job:
  stage: build
  script:
    - echo "Building the application..."
    - echo "Build completed!"

# Test stage
test_job:
  stage: test
  script:
    - echo "Running tests..."
    - echo "All tests passed successfully!"

# Deploy stage
deploy_job:
  stage: deploy
  script:
    - echo "Deploying application..."
    - echo "Deployment completed successfully!"
```

That’s all you need for GitLab to detect your pipeline.

---

## ⚙️ Step 3: Push the File to GitLab

1. Save `.gitlab-ci.yml` in your local repo.
2. Commit and push it:

```bash
git add .gitlab-ci.yml
git commit -m "Add GitLab CI/CD pipeline"
git push origin main
```

---

## 🔄 Step 4: Verify Automatic Trigger

After pushing:

1. Go to **GitLab → Your Project → CI/CD → Pipelines**.
2. You’ll see the pipeline **automatically triggered** for your push.

---

## 🧠 Optional: Trigger Only on Specific Branches

If you want the pipeline to run only for a specific branch (e.g., `main`):

```yaml
build_job:
  stage: build
  script:
    - echo "Building..."
  only:
    - main
```

Or for all branches except `dev`:

```yaml
except:
  - dev
```

---

## 🧩 Step 5 (Optional): Add Conditions (like file change detection)

To trigger the pipeline only when certain files are modified:

```yaml
build_job:
  stage: build
  script:
    - echo "Rebuilding..."
  rules:
    - changes:
        - src/**/*
```

---

## ✅ Summary

| Step | Action                  | Description                              |
| ---- | ----------------------- | ---------------------------------------- |
| 1    | Configure Runner        | Shared or specific runner must be active |
| 2    | Create `.gitlab-ci.yml` | Define build/test/deploy stages          |
| 3    | Push changes            | Triggers pipeline                        |
| 4    | View pipeline           | GitLab → CI/CD → Pipelines               |
| 5    | (Optional)              | Add branch rules or file-change rules    |

> Let’s create a **complete GitLab CI/CD pipeline** that demonstrates *all the main triggering scenarios* — each handled in a **different build job** so you can see how they behave in real projects.

This is ideal for learning and reference.

---

## ⚙️ `.gitlab-ci.yml` — Full Example Covering All Trigger Scenarios

```yaml
# -----------------------------------
# Complete GitLab CI/CD Example
# Demonstrating All Trigger Types
# -----------------------------------

stages:
  - build
  - test
  - deploy
  - conditional
  - manual
  - scheduled

# -----------------------------------
# 1️⃣ Run on Every Push (Default Behavior)
# -----------------------------------
build_every_push:
  stage: build
  script:
    - echo "✅ This job runs on EVERY PUSH (default)."
    - echo "Triggered by a push to any branch."

# -----------------------------------
# 2️⃣ Run Only on 'main' Branch
# -----------------------------------
build_main_only:
  stage: build
  script:
    - echo "🧱 This job runs only on MAIN branch."
  only:
    - main

# -----------------------------------
# 3️⃣ Run Only on Merge Requests
# -----------------------------------
test_on_merge_request:
  stage: test
  script:
    - echo "🧪 Running tests for merge request validation..."
  only:
    - merge_requests

# -----------------------------------
# 4️⃣ Run Only When Specific Files Change
# -----------------------------------
build_on_code_change:
  stage: build
  script:
    - echo "📂 Code files changed, running build..."
  rules:
    - changes:
        - src/**/*     # only if files inside src/ folder changed
        - app/**/*

# -----------------------------------
# 5️⃣ Skip When Only Docs Changed
# -----------------------------------
skip_on_docs_change:
  stage: test
  script:
    - echo "🧾 Docs changed only, so this job will NOT run."
  rules:
    - changes:
        - "*.md"
      when: never
    - when: on_success

# -----------------------------------
# 6️⃣ Manual Trigger Job (Requires Click)
# -----------------------------------
manual_deploy:
  stage: deploy
  script:
    - echo "🚀 Deploying manually..."
  when: manual
  only:
    - main

# -----------------------------------
# 7️⃣ Run on a Schedule (via GitLab Scheduler)
# -----------------------------------
scheduled_cleanup:
  stage: scheduled
  script:
    - echo "🧹 Running nightly cleanup..."
  only:
    - schedules

# -----------------------------------
# 8️⃣ Conditional Job (example: only if variable set)
# -----------------------------------
conditional_job:
  stage: conditional
  script:
    - echo "🔑 Conditional variable-based job executed."
  rules:
    - if: '$RUN_EXTRA == "true"'
      when: always
    - when: never
```

---

## 🧠 Explanation

| Scenario               | Job Name                | Description                                        |
| ---------------------- | ----------------------- | -------------------------------------------------- |
| Every push             | `build_every_push`      | Default — runs for all branches                    |
| Only main branch       | `build_main_only`       | Runs only on `main` branch                         |
| On merge requests      | `test_on_merge_request` | Runs when a merge request is opened/updated        |
| On file changes        | `build_on_code_change`  | Triggers only if files in `src/` or `app/` changed |
| Skip docs-only changes | `skip_on_docs_change`   | Skips if only `.md` files were updated             |
| Manual trigger         | `manual_deploy`         | Must be triggered manually in GitLab UI            |
| Scheduled              | `scheduled_cleanup`     | Runs from CI/CD → Schedules                        |
| Variable-based         | `conditional_job`       | Runs only if variable `RUN_EXTRA=true` is set      |

---

## 🧩 Step-by-Step to Test These

1. **Create `.gitlab-ci.yml`** with the above content.
2. **Commit & push** to your repo:

   ```bash
   git add .gitlab-ci.yml
   git commit -m "Add advanced GitLab CI pipeline covering all trigger types"
   git push origin main
   ```
3. Go to **GitLab → CI/CD → Pipelines** and observe:

   * Pipeline runs automatically on push.
   * Try different branches, merge requests, file types, or variables to see jobs triggering/skipping.
