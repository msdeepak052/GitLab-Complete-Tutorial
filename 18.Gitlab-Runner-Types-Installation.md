## **1️⃣ What is a GitLab Runner?**

* A **GitLab Runner** is an **agent that runs jobs from your GitLab CI/CD pipelines**.
* GitLab itself schedules jobs, but the Runner **executes the scripts** defined in your `.gitlab-ci.yml`.
* Jobs can run on **your local machine, cloud server, Docker container, or Kubernetes cluster**, depending on the runner type.

---

## **2️⃣ GitLab Runner Types**

There are **two main types**: **Shared Runners** and **Specific Runners**.

### **A. Shared Runners**

* **Definition**: Runners available to **all projects in a GitLab instance**.
* **Use Case**: Great for small projects or when you don’t want to manage your own runner.
* **Example**: GitLab.com provides shared runners with Docker and shell executors.
* **Advantages**:

  * No setup required (if GitLab provides shared runners)
  * Useful for testing or smaller teams
* **Disadvantages**:

  * Jobs **share resources** with other projects → may be slower
  * Less control over environment

---

### **B. Specific (or Private) Runners**

* **Definition**: Runners **dedicated to a specific project or group**.
* **Use Case**: When you need **full control** over the environment, software, and security.
* **Advantages**:

  * Complete control over OS, dependencies, and resources
  * Can run jobs that need privileged access
* **Disadvantages**:

  * You must manage and maintain the runner yourself

---

### **3️⃣ GitLab Runner Executors**

Runners can execute jobs in different ways. Common **executor types**:

| Executor                         | Description                               | Use Case                                   |
| -------------------------------- | ----------------------------------------- | ------------------------------------------ |
| **Shell**                        | Runs job scripts directly on host OS      | Simple setups, Linux/Windows servers       |
| **Docker**                       | Runs each job in a **Docker container**   | Isolated builds, reproducible environments |
| **Docker Machine**               | Dynamically creates Docker hosts for jobs | Scalable CI/CD for many jobs               |
| **Kubernetes**                   | Runs jobs in Kubernetes pods              | Cloud-native CI/CD pipelines               |
| **VirtualBox / Parallels / SSH** | Runs jobs in VM or remote server via SSH  | Legacy setups or custom environments       |

## **4️⃣ Installing GitLab Runner**

You can install a runner on **Linux, Windows, or macOS**. Here’s an example for **Linux (Ubuntu/Debian)**:

### **Step 1: Add GitLab Runner repository**

```bash
# Add repository
curl -L https://packages.gitlab.com/install/repositories/runner/gitlab-runner/script.deb.sh | sudo bash
```

### **Step 2: Install GitLab Runner**

```bash
sudo apt-get install gitlab-runner
```

### **Step 3: Register the Runner**

```bash
sudo gitlab-runner register
```

You’ll be prompted for:

1. **GitLab URL** → e.g., `https://gitlab.com/`
2. **Registration token** → Found in GitLab **Project → Settings → CI/CD → Runners**
3. **Description** → Any name for the runner
4. **Tags** → Optional, useful for tagging jobs
5. **Executor** → e.g., `shell`, `docker`, `kubernetes`
6. **Docker image** → If using Docker executor, e.g., `alpine:latest`

### **Step 4: Start the Runner**

```bash
sudo gitlab-runner start
```

✅ Runner is now ready to pick up jobs from your project.

---

## **5️⃣ Installing on Windows**

1. Download the **GitLab Runner binary** from:
   `https://gitlab-runner-downloads.s3.amazonaws.com/latest/binaries/gitlab-runner-windows-amd64.exe`
2. Move it to `C:\GitLab-Runner\gitlab-runner.exe`
3. Register runner via CMD:

```cmd
gitlab-runner.exe register
gitlab-runner.exe install
gitlab-runner.exe start
```

---

## **6️⃣ Installing with Docker (Optional)**

```bash
docker run -d --name gitlab-runner --restart always \
  -v /srv/gitlab-runner/config:/etc/gitlab-runner \
  -v /var/run/docker.sock:/var/run/docker.sock \
  gitlab/gitlab-runner:latest
```

* This is useful for **isolated environments** or **cloud CI/CD setups**.

---

### **7️⃣ Key Takeaways**

* **Shared runners** → for all projects, easy to use.
* **Specific runners** → dedicated, more control.
* **Executor types** → shell, docker, Kubernetes, etc.
* **Installation** → Linux/Windows/macOS, or Docker.
* **Registration** → Connects runner to GitLab project with a token.
