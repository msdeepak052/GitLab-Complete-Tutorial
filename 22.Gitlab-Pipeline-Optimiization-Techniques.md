Let’s go **deep into GitLab CI/CD pipeline optimization**. I’ll cover practical techniques with examples so you can **speed up pipelines, reduce redundant work, and save resources**.

---

# **1️⃣ Use `only/except` or `rules` to Run Jobs Conditionally**

* Run jobs **only when needed** instead of every commit.
* Reduces pipeline runtime and unnecessary resource usage.

### **Example: Run deploy only on main branch**

```yaml
deploy_job:
  stage: deploy
  script:
    - echo "Deploying application..."
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
```

* Deploy job runs **only on main branch**, skipping feature branches.
* Old way: `only: [main]` and `except: [develop]`.

---

# **2️⃣ Use `needs` to Run Jobs in Parallel**

* Normally jobs run **stage by stage**, waiting for all previous jobs.
* `needs:` allows a job to **run immediately after its dependencies**, bypassing stage order.

### **Example: Run tests as soon as build is ready**

```yaml
stages:
  - build
  - test

build_job:
  stage: build
  script:
    - echo "Building app..."

unit_tests:
  stage: test
  script:
    - echo "Running unit tests..."
  needs: ["build_job"]
```

* `unit_tests` runs **immediately after build_job finishes**, instead of waiting for the whole build stage.

---

# **3️⃣ Split Jobs and Use Parallelism**

* Split **large tasks** into multiple **parallel jobs**.
* Use `parallel:` or `matrix:` for **faster execution**.

### **Example: Parallel tests**

```yaml
unit_tests:
  stage: test
  script:
    - echo "Running test suite $CI_NODE_INDEX"
    - ./run_tests.sh --part $CI_NODE_INDEX
  parallel: 4
```

* Four jobs run **simultaneously**, splitting the test suite.

---

# **4️⃣ Use Caching to Avoid Rebuilding/Downloading Dependencies**

* Use **`cache:`** to store **dependencies** like `node_modules` or `pip packages`.

### **Example: Node.js caching**

```yaml
stages:
  - build

build_job:
  stage: build
  script:
    - npm install
    - npm run build
  cache:
    key: ${CI_COMMIT_REF_SLUG}
    paths:
      - node_modules/
```

✅ **Explanation**:

* Next pipeline reuses `node_modules` from cache → faster build.

---

# **5️⃣ Use Artifacts to Share Results Between Jobs**

* Instead of rerunning steps, **save output as artifacts**.

### **Example: Build and test using artifacts**

```yaml
stages:
  - build
  - test

build_job:
  stage: build
  script:
    - npm run build
  artifacts:
    paths:
      - dist/

test_job:
  stage: test
  dependencies:
    - build_job
  script:
    - ls dist/
```

* `test_job` **reuses the build output**, avoids rebuilding.

---

# **6️⃣ Use `include` or Child Pipelines for Large Pipelines**

* Break **monolithic `.gitlab-ci.yml`** into **smaller files** or **child pipelines**.
* Helps **maintain modular pipelines** and allows **parallel execution** of child pipelines.

### **Example: Include files**

```yaml
include:
  - local: 'ci-templates/build.yml'
  - local: 'ci-templates/test.yml'
```

* Only jobs in included files are run → easier to maintain.

---

# **7️⃣ Limit Jobs with Tags and Runners**

* Assign **tags** to jobs and runners to **avoid idle jobs waiting for the wrong runner**.

### **Example: Run Docker jobs on Docker runners only**

```yaml
docker_build:
  stage: build
  script:
    - docker build -t myapp .
  tags:
    - docker
```

* Job runs **only on runners with Docker installed**, reducing failures and wasted resources.

---

# **8️⃣ Use `rules:changes` to Run Jobs Only When Files Change**

* Avoid running jobs for unrelated changes.

### **Example: Run frontend build only if frontend files change**

```yaml
frontend_build:
  stage: build
  script:
    - npm install
    - npm run build
  rules:
    - changes:
        - frontend/**
```

✅ Saves **time and resources** for changes that don’t affect all layers.

---

# **9️⃣ Use `extends` to Avoid Repetition**

* Define **common job templates** and extend them in multiple jobs.
* Keeps YAML **DRY (Don’t Repeat Yourself)**.

### **Example:**

```yaml
.default_job: &default_job
  image: node:20
  before_script:
    - npm ci

build_job:
  <<: *default_job
  stage: build
  script:
    - npm run build

test_job:
  <<: *default_job
  stage: test
  script:
    - npm test
```

* Both jobs reuse **common settings**, easy to maintain.

---

# **🔑 Summary of Optimization Techniques**

| Technique                   | Purpose                                     |
| --------------------------- | ------------------------------------------- |
| `rules/only/except`         | Run jobs conditionally                      |
| `needs`                     | Run jobs in parallel across stages          |
| `parallel` / `matrix`       | Split work to reduce runtime                |
| `cache`                     | Reuse dependencies                          |
| `artifacts`                 | Share outputs between jobs                  |
| `include` / child pipelines | Modular pipelines, separate logic           |
| Tags / runners              | Assign jobs to specific runners efficiently |
| `rules:changes`             | Run jobs only when specific files change    |
| `extends`                   | Avoid repetition in job definitions         |
