## **1️⃣ Parallel Builds**

**Parallel builds** allow multiple **instances of the same job to run at the same time**.

* Useful for speeding up **tests** or **builds** that can run independently.
* Controlled with the **`parallel:`** keyword in GitLab.

---

### **Syntax**

```yaml
job_name:
  stage: test
  script:
    - echo "Running test $CI_NODE_INDEX of $CI_NODE_TOTAL"
  parallel: 3
```

* `parallel: 3` → GitLab will run **3 instances of the job simultaneously**.
* **Environment variables for each instance**:

  * `$CI_NODE_INDEX` → the instance number (1 to total)
  * `$CI_NODE_TOTAL` → total number of parallel instances

---

### **Example: Parallel Tests**

```yaml
stages:
  - test

unit_tests:
  stage: test
  script:
    - echo "Running test suite $CI_NODE_INDEX of $CI_NODE_TOTAL"
  parallel: 4
```

✅ **Explanation**:

* GitLab runs 4 parallel jobs:

  ```
  Running test 1 of 4
  Running test 2 of 4
  Running test 3 of 4
  Running test 4 of 4
  ```
* Each job runs **independently** and speeds up the overall test stage.

---

## **2️⃣ Matrix Builds (Matrix Jobs)**

**Matrix builds** allow running **a job multiple times with different variables**.

* Useful for testing **different combinations of environments**, **OS versions**, **language versions**, or **configurations**.
* Controlled with the **`parallel:matrix`** keyword.

---

### **Syntax**

```yaml
job_name:
  stage: test
  script:
    - echo "Running on $OS and $BROWSER"
  parallel:
    matrix:
      - OS: ["ubuntu", "alpine"]
        BROWSER: ["chrome", "firefox"]
```

✅ GitLab will automatically create **all combinations**:

| OS     | BROWSER |
| ------ | ------- |
| ubuntu | chrome  |
| ubuntu | firefox |
| alpine | chrome  |
| alpine | firefox |

---

### **Full Example: Matrix Build for Testing**

```yaml
stages:
  - test

cross_platform_tests:
  stage: test
  script:
    - echo "Running tests on $OS with $BROWSER"
  parallel:
    matrix:
      - OS: ["ubuntu", "alpine"]
        BROWSER: ["chrome", "firefox"]
```

**What happens**:

* GitLab creates **4 jobs**:

  1. `ubuntu + chrome`
  2. `ubuntu + firefox`
  3. `alpine + chrome`
  4. `alpine + firefox`
* Each job **runs independently** in parallel (depending on available runners).

---

### **3️⃣ Key Differences: Parallel vs Matrix**

| Feature    | Parallel                                      | Matrix                                           |
| ---------- | --------------------------------------------- | ------------------------------------------------ |
| Purpose    | Run **multiple identical jobs** to split load | Run **job with different variable combinations** |
| Definition | `parallel: <number>`                          | `parallel: matrix:`                              |
| Variables  | `$CI_NODE_INDEX`                              | Custom variables defined in matrix               |
| Use Case   | Split large test suite, speed up build        | Test multiple OS, versions, configurations       |

---

### **4️⃣ Combining Parallel and Matrix**

You can even **combine both** for **maximum parallelism**:

```yaml
stages:
  - test

cross_env_tests:
  stage: test
  script:
    - node --version
    - echo "Running on $OS with Node $NODE_VERSION"
    - npm install
    - npm test
  parallel:
    matrix:
      - OS: ["ubuntu:22.04", "alpine:3.18"]
        NODE_VERSION: ["18", "20"]
    total: 2  # Optional: run 2 instances per combination
```

* This allows **splitting each matrix job into multiple parallel instances**, speeding up CI/CD pipelines.

---

### **5️⃣ Key Takeaways**

* **Parallel builds** → run the same job multiple times in parallel to reduce time.
* **Matrix builds** → run the job across **different variables/combinations** automatically.
* Both improve **pipeline speed and coverage**.
* Combine with tags and runners for **dynamic environments**.
