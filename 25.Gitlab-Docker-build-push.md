# Understand how GitLab CI/CD builds and pushes Docker images to a registry


## 🧩 **1. What It Means**

Using **GitLab CI/CD for Docker builds** means:

* Your CI pipeline automatically **builds Docker images** from a `Dockerfile`.
* Then **pushes** the image to a container registry (Docker Hub or GitLab’s built-in registry).

---

## ⚙️ **2. Key Requirements**

1. A **Dockerfile** in your repository.
   Example:

   ```Dockerfile
   FROM node:18-alpine
   WORKDIR /app
   COPY . .
   RUN npm install
   CMD ["npm", "start"]
   ```

2. GitLab Runner with **Docker-in-Docker (dind)** support or Docker socket access.
   (More on that below.)

3. Credentials for your registry — stored as **GitLab CI/CD variables** (Settings → CI/CD → Variables):

   * `DOCKER_USERNAME`
   * `DOCKER_PASSWORD`
   * `DOCKER_REGISTRY` (optional if using Docker Hub)

---

## 🚀 **3. Example: Build & Push to Docker Hub**

Here’s a **working `.gitlab-ci.yml`**:

```yaml
image: docker:latest

services:
  - docker:dind  # Docker-in-Docker service

variables:
  DOCKER_DRIVER: overlay2
  IMAGE_NAME: deepakyadav/devops-app
  IMAGE_TAG: $CI_COMMIT_SHORT_SHA  # short commit hash

stages:
  - build
  - push

before_script:
  - docker login -u "$DOCKER_USERNAME" -p "$DOCKER_PASSWORD"

build_image:
  stage: build
  script:
    - docker build -t $IMAGE_NAME:$IMAGE_TAG .
    - docker images
  artifacts:
    paths:
      - Dockerfile
    expire_in: 1 hour

push_image:
  stage: push
  script:
    - docker push $IMAGE_NAME:$IMAGE_TAG
  only:
    - main
```

---

## 🔍 **4. Step-by-Step Explanation**

| Step                    | Description                                                       |
| ----------------------- | ----------------------------------------------------------------- |
| `image: docker:latest`  | Uses Docker CLI image to run commands inside the CI job.          |
| `services: docker:dind` | Enables Docker daemon inside GitLab Runner to build images.       |
| `before_script`         | Logs into Docker Hub using credentials.                           |
| `build_image`           | Builds the Docker image using your Dockerfile.                    |
| `push_image`            | Pushes the image to Docker Hub.                                   |
| `only: main`            | Ensures push happens **only** when committing to the main branch. |

---

## 🧱 **5. Example for GitLab Container Registry**

You can also use GitLab’s built-in registry.
Change the registry path and login method:

```yaml
variables:
  IMAGE_NAME: $CI_REGISTRY_IMAGE/myapp
  IMAGE_TAG: $CI_COMMIT_SHORT_SHA

before_script:
  - docker login -u "$CI_REGISTRY_USER" -p "$CI_REGISTRY_PASSWORD" $CI_REGISTRY
```

Now it builds and pushes to your project’s registry like:

```
registry.gitlab.com/username/projectname/myapp:abcd123
```

---

## ✅ **6. Optional Enhancements**

* **Cache Docker layers** to speed up builds:

  ```yaml
  variables:
    DOCKER_BUILDKIT: 1
    DOCKER_CACHE_FROM: $IMAGE_NAME:latest
  ```

* **Push multiple tags** (e.g., latest + commit hash):

  ```yaml
  script:
    - docker build -t $IMAGE_NAME:$CI_COMMIT_SHORT_SHA -t $IMAGE_NAME:latest .
    - docker push $IMAGE_NAME --all-tags
  ```

* **Trigger Deploy Stage** after push to deploy image to EC2, EKS, or another environment.

## 💡 Summary

| Concept                           | Meaning                                       |
| --------------------------------- | --------------------------------------------- |
| **Docker-in-Docker (dind)**       | Allows building Docker images inside CI jobs. |
| **before_script**                 | Used for Docker login.                        |
| **build + push jobs**             | Separate build and push responsibilities.     |
| **GitLab Registry or Docker Hub** | Destination for your built images.            |

Let’s take the pipeline to the **next real-world level** by adding a **deploy stage to AWS EC2** after building and pushing your Docker image.

We’ll assume you already have:

* ✅ An **EC2 instance** (Amazon Linux or Ubuntu) with **Docker installed**
* ✅ SSH access via a private key
* ✅ A **Docker image** pushed to Docker Hub (or GitLab registry)

---

## ⚙️ **1. Prerequisites on AWS EC2**

On your EC2 instance:

```bash
sudo yum install docker -y
sudo systemctl start docker
sudo usermod -aG docker ec2-user
```

Then make sure:

* You can **SSH into EC2** using your private key.
* Your EC2’s **security group** allows inbound SSH (port 22) and HTTP (port 80) if it’s a web app.

---

## 🔐 **2. Add CI/CD Variables in GitLab**

Go to **Settings → CI/CD → Variables** and add:

| Variable Name     | Description                                            |
| ----------------- | ------------------------------------------------------ |
| `DOCKER_USERNAME` | Docker Hub username                                    |
| `DOCKER_PASSWORD` | Docker Hub password or token                           |
| `EC2_HOST`        | Public IP or hostname of your EC2                      |
| `EC2_USER`        | `ec2-user` (for Amazon Linux) or `ubuntu` (for Ubuntu) |
| `SSH_PRIVATE_KEY` | Your PEM key content (copied from `.pem` file)         |

---

## 🚀 **3. Full `.gitlab-ci.yml` Example**

```yaml
image: docker:latest

services:
  - docker:dind

variables:
  DOCKER_DRIVER: overlay2
  IMAGE_NAME: deepakyadav/devops-app
  IMAGE_TAG: $CI_COMMIT_SHORT_SHA
  DOCKER_BUILDKIT: 1

stages:
  - build
  - push
  - deploy

before_script:
  - docker login -u "$DOCKER_USERNAME" -p "$DOCKER_PASSWORD"

# 🧱 Build Docker Image
build_image:
  stage: build
  script:
    - echo "Building Docker image..."
    - docker build -t $IMAGE_NAME:$IMAGE_TAG .
    - docker tag $IMAGE_NAME:$IMAGE_TAG $IMAGE_NAME:latest

# 📦 Push Docker Image
push_image:
  stage: push
  script:
    - echo "Pushing Docker image..."
    - docker push $IMAGE_NAME:$IMAGE_TAG
    - docker push $IMAGE_NAME:latest
  needs: ["build_image"]
  only:
    - main

# 🚀 Deploy to AWS EC2
deploy_to_ec2:
  stage: deploy
  image: alpine:latest
  before_script:
    # Install SSH client
    - apk add --no-cache openssh
    # Write SSH key to file
    - echo "$SSH_PRIVATE_KEY" > private_key.pem
    - chmod 600 private_key.pem
  script:
    - echo "Deploying to EC2..."
    - ssh -o StrictHostKeyChecking=no -i private_key.pem $EC2_USER@$EC2_HOST "
        docker login -u $DOCKER_USERNAME -p $DOCKER_PASSWORD &&
        docker pull $IMAGE_NAME:latest &&
        docker stop devops-app || true &&
        docker rm devops-app || true &&
        docker run -d -p 80:80 --name devops-app $IMAGE_NAME:latest
      "
  needs: ["push_image"]
  only:
    - main
```

---

## 🧠 **4. How It Works**

| Stage      | What Happens                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| **Build**  | Creates Docker image from your Dockerfile.                                                                  |
| **Push**   | Pushes the built image to Docker Hub or GitLab Container Registry.                                          |
| **Deploy** | SSHs into your EC2 instance, pulls the new image, stops old container (if running), and starts a fresh one. |

---

## 🔍 **5. EC2 Commands Explained**

When GitLab runs the deploy job:

```bash
docker login -u $DOCKER_USERNAME -p $DOCKER_PASSWORD
docker pull deepakyadav/devops-app:latest
docker stop devops-app || true
docker rm devops-app || true
docker run -d -p 80:80 --name devops-app deepakyadav/devops-app:latest
```

* Pulls latest image
* Stops and removes any old container
* Runs the new container on port 80


| `only: main`      | Ensures deployment happens only on main branch |
